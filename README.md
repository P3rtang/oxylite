# offline-notes

Offline-first notes app demonstrating the stack it could grow from into a small library:

| Piece | Tech |
|---|---|
| Client UI | Dioxus (wasm/web) |
| Client DB | PGlite, persisted in IndexedDB |
| Server | Axum + Tokio |
| Server DB | Postgres via sqlx |

## Architecture

```
┌────────────────────────────────┐         ┌─────────────────────────┐
│ Dioxus UI (wasm)               │         │ Axum server (tokio)     │
│   │                            │         │   /sync      (WS push/  │
│ sync engine (JSON over WS)     │◄─:3000──┤   /pglite/   (module)   │
│   one task; JS callbacks only  │         │   /*         (dist/)    │
│ enqueue, a session loop drains │         │   sqlx → Postgres       │
│ PGlite (idb://offline_notes)   │         │     (sync_log table)    │
└────────────────────────────────┘         └─────────────────────────┘
```

- Everything is **single-origin** on `http://localhost:3000`: the built dioxus
  client (dist), the vendored PGlite bundle (`/pglite/`), and the WS (`/sync`)
  are all served by the axum server.
- Writes go to **PGlite first** (offline works), then are **pushed** to the
  server; while offline they queue durably (an IndexedDB op log) and flush on
  reconnect.
- **Multi-tab is single-writer**: one leader tab owns the PGlite connection
  (elected via Web Locks); follower tabs proxy writes to it over a
  BroadcastChannel. An offline write in any tab — even one that closes before
  reconnecting — still syncs.
- The server appends every change to a `sync_log` table with a monotonic
  `seq` and streams changes to connected sockets (500 ms ticker) plus
  explicit `Pull`s (at-least-once; LWW upsert makes re-delivery harmless).
- **Deletes are ops too**: a delete is an op whose payload is `null`. Every
  upsert checks a lib-owned tombstone table first, so a stale edit arriving
  after a delete cannot resurrect the row. Tombstones ride along with
  snapshots so far-behind clients (who never replay the delete op) stay
  consistent too.
- Schema migrations live in one directory (`crates/shared/migrations/`) and
  are applied by both sides: the server via `sqlx::migrate!`, each client on
  first boot against its own PGlite (apply-once, tracked in a `meta` table).
  The list is generated by a build script — adding a migration file is the
  whole job, and naming violations fail the build.
- The client persists its sync **cursor in PGlite** itself (`meta` table), so
  pulls resume after reloads.

Wire protocol (see `crates/shared`):

```json
C->S  {"type":"Pull","since":42}
C->S  {"type":"Push","ops":[{"table":"notes","id":"…","data":{…},"updated_at":"…"}]}
      // a delete is the same op with "data":null
S->C  {"type":"Ack","cursor":57}
S->C  {"type":"Events","events":[…],"cursor":57}
S->C  {"type":"Snapshot","seq":57,"tables":[…],"tombstones":[…]}
```

## Setup

```bash
# dev loop with hot reload: axum on :3000, dx dev server on :8081
# (proxies /sync and /pglite to :3000 — open http://localhost:8081)
./scripts/dev.sh

# one command: postgres + server + built client, opens the browser
./scripts/browser.sh
```

Manually, piece by piece:

```bash
podman compose up -d            # Postgres
./scripts/vendor-pglite.sh      # one-time: vendor PGlite 0.5.8 into assets
cargo build -p server           # axum + tokio + sqlx
DX=~/.cargo/bin/dx ./scripts/build-client.sh   # dioxus web build -> crates/client/dist
./scripts/serve-server.sh       # serves app + pglite + ws on :3000
```

Open http://localhost:3000, add notes, kill the server, keep writing —
everything persists locally in IndexedDB and syncs once the server returns.
Console logs are tagged `[boot]` / `[sync]` / `[pglite]` for DevTools.

## Tests

```bash
./test.sh                       # everything: lint (fmt, clippy, cargo test) + e2e
./test.sh --e2e                 # Playwright suite only (bun); manages the stack itself
./test.sh --e2e tests/sync/delete.spec.ts   # args pass through to playwright
```

16 Playwright specs in two groups: `app/` (UI behavior) and `sync/`
(offline queue, multi-tab, delete/tombstone contracts, snapshot
bootstrap, error notices). Rust contracts live as integration targets
in `crates/*/tests/` (delete semantics, generated-SQL shapes, and
server-side tests that PREPARE-check every generated client statement
against the migrated schema).

## Path to a library

`crates/oxylite` is the library candidate (engine, protocol, PGlite
bridge, query layer); the notes app is the proof vehicle. Done:
single-source migrations applied on both sides, offline-first with a
durable op log, multi-tab single-writer, deletes/tombstones, snapshots
for far-behind clients, typed errors surfaced as notices. Remaining,
roughly in order: transactions & conflict semantics, schema evolution
for shipped clients, identity/scoping, and CI + structured logging —
the backlog lives in the repo's internal docs.
